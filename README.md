# TaskFlow

A general-purpose task manager. The complete backend is Java with Spring Boot, Spring Data JPA, and MySQL. The browser UI is plain HTML, CSS, and JavaScript and talks to the Java REST API.

## Run locally

In PowerShell, from this folder run `.\start-taskflow.ps1` and open `http://localhost:8081`. The launcher uses the tools set up in `.tools`, starts MySQL if needed, waits for it, and runs the app. Press Ctrl+C to stop the app.

Hibernate creates/updates the account, category, and six profile task tables on startup. Existing tasks are migrated once into their profile table; sign-up assigns legacy tasks in that profile to the first account created. Set database credentials outside source control for shared or deployed environments.

## Features

- Create, view, edit, and delete tasks.
- Set optional descriptions and date-and-time deadlines, priority, and pending/in-progress/completed status.
- Filter by status and priority; search task titles and descriptions.
- Dashboard counts plus an attention indicator for overdue and due-today tasks.
- Landing page with sign up and log in. Accounts select a profile at sign up and open its workspace after authentication.
- Separate task tables for personal, student, office worker, freelancer, business owner, and teacher profiles. Tasks are also scoped to the signed-in account.
- Domain-based task categories stored in a dedicated `task_categories` table; tasks can be assigned to a category.
- Rule-based task tips generated by Java from open tasks, priorities, and deadlines; no AI service is used.
- Downloadable CSV reports with task summaries and optional deadline date range.
- Responsive layout for desktop and mobile screens.

## REST API

- `GET /api/tasks?status=PENDING&priority=HIGH` (filters optional)
- `GET /api/tasks/{id}`
- `POST /api/tasks`
- `PUT /api/tasks/{id}`
- `DELETE /api/tasks/{id}`
- `GET /api/dashboard`
- `GET /api/categories`, `POST /api/categories`
- `GET /api/tips`
- `GET /api/reports.csv?from=YYYY-MM-DD&to=YYYY-MM-DD` (date filters optional)
- `GET /api/auth/csrf` (required before POST requests; send its token in `X-CSRF-TOKEN`)
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`

Tasks are stored in `tasks_personal`, `tasks_student`, `tasks_office_worker`, `tasks_freelancer`, `tasks_business_owner`, or `tasks_teacher`, selected from the account profile. Each task row also carries an `owner_id`, keeping accounts within a profile separate. Task JSON uses `title`, `description`, `priority` (`LOW`, `MEDIUM`, `HIGH`), `status` (`PENDING`, `IN_PROGRESS`, `COMPLETED`), optional local date-time `deadline` (`YYYY-MM-DDTHH:MM:SS`), and optional `categoryId`. Existing tasks are copied to their profile table on startup with no owner; the first account registered under that profile adopts those older tasks. The source table is retained as `tasks_legacy`.
